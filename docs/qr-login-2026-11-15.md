# 红果 App 扫码登录

设置页使用原生扫码界面，移除了 Cookie、Token 输入和剪贴板导入。点击“立即登录”或“切换账号”获取二维码，手机红果 App 扫码并确认后自动保存登录态；保留现有账号直到新登录完整校验并保存成功。

## 协议与实现

固定版本及当前上游 OpenHongguo SDK 均只有匿名认证实现。本功能由独立的 Go `internal/qrauth` 实现官网 Passport 协议，协议线索参考 [hongguoTV WebLogin](https://github.com/tsukiyo-zero/hongguoTV/blob/77a99f509b8a5c586bf6ef453147cf1003203970/kotlin-tv/core/src/main/kotlin/com/hongguotv/core/WebLogin.kt)，没有修改 SDK 模块缓存。

- 官网 `https://hongguoduanju.com`，Web aid=513755。
- 获取：`GET /passport/web/get_qrcode/`。
- 状态：`GET /passport/web/check_qrconnect/`。
- 手机确认后的会话校验：`GET /passport/account/info/v2/`。
- 确认成功后使用既有官方账号资料读取及 SQLite 账号事务，自动接入主设备、SDK 认证 transport、历史与收藏；不借用播放备用设备的身份。

每次扫码使用独立内存 CookieJar，二维码 token 不进入公共 DTO、日志或磁盘。仅向 UI 返回本机尝试 ID、二维码 PNG 和官方过期时间。轮询保存 CSRF Cookie，确认跳转限定官方 HTTPS 同域；必须同时得到手机确认、有效会话、Passport 校验及有效官方账号资料，才写入账号。

二维码有效期由响应决定，真实测试中为 60 秒。HTTP 5xx 和网络中断使用有界重试，保留原会话。手机已确认的阶段会记住确认结果，在二维码过期后仍可完成会话校验及资料读取，避免 502 导致重新扫码。永久错误、拒绝和过期不会被当作登录成功。

打开、取消、刷新二维码、离开设置、窗口关闭都会通过 context 和尝试版本终止旧流程。迟到结果不能发布新身份。登录发布与账号更改串行化，确认前检查原账号未变化；保存前再次检查取消。资料刷新在同一账号锁内取得凭据，避免旧刷新结果恢复旧登录态。成功登录使旧的页面请求失效。

同账号扫码保留历史；真正换号才切换可见数据范围，旧待同步操作仍留在原账号范围。失败和取消保留当前账号及其历史。

## 原生 UI

核对 MyGo v0.9.1 官方组件：二维码使用 `Image` / `DecodeBitmap`，操作使用 `ButtonBase`，分隔使用 `Divider`；图片在后台解码一次，不在渲染帧内做网络或解码。固定二维码区域保持刷新过程布局稳定，白色静区便于扫描，其余沿用应用暗色风格。不放置加载动画或加载提示文字，只展示必要的手机确认及异常状态。

- 单测覆盖 CSRF 会话连续性、扫码前不泄露凭据、手机确认及 Passport 双重验证、非法跳转、错误脱敏、拒绝/过期、502 后继续原会话并跨越二维码过期时间。

- UI 覆盖替换输入框、800/1400 宽布局、扫码状态、成功收起、取消/离开后忽略旧结果、失败后刷新。布局截图 `/tmp/myguo-qr-ui/settings-qr-login.png`。
