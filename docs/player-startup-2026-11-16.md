# 推荐流无分集作品与玻璃首屏修复

## 现象与证据

- 《美食掌柜第七季》（`7706480823213509656`）反复提示视频加载失败。
- 安装版日志在分集解析阶段报告 `anonymous response was empty`，尚未进入播放流加载。
- 隔离匿名设备实测：单剧详情没有分集；批量详情也没有分集，数量为 0，状态文案为“全0集”。因此这次不能归因为网络断连，也不能据此保证该剧未来可播放。
- 当前 SDK 把成功但无分集的单剧详情也归为 `ErrAnonymousLimited`，原应用可能因此重置设备并反复尝试同一作品。
- 应用启动前已设置原生暗色主题。玻璃使用 `plugins/glass` 的 native 模式，从 UI 表面下方取样；封面却画在 UI 内。在 AVKit 首帧出现前取样窗口底，会造成首屏灰白。

## 实现

- 分集请求遇到 SDK 空响应时，在现有请求合并范围内追加一次批量详情校验。批量有分集则恢复；数量为 0、无分集，且有“全0集”或待上线文案，才标记 `ErrNoPlayableEpisodes`。信息不足时仍保留原有错误处理。
- 确认无分集后不重置设备。推荐流消费并移除此项，播放下一部；队尾等待补页时保留目标索引，过滤空页后继续前进，耗尽后结束等待。普通网络错误保留重试，不自动跳过。
- 推荐元数据中的“全0集”覆盖旧的非零数量，并从本地待播队列移除。
- 首帧前、播放失败或画中画期间使用 UI 表面的 shader 玻璃；AVKit `Ready && Displayed` 后切换 native 玻璃。两种模式使用同样的 clear 风格和黑色 40% tint。侧栏、频道、菜单按钮统一使用该选择。
- 继续使用官方 `plugins/glass.Glass`，没有自制玻璃绘制或添加互动材质动画。页面材质与播放器材质分别依据所在图层取样。

## 验证

- 后端回归覆盖：空分集确认、有分集批量恢复、信息不足不误判或移出推荐、设备不重复注册、旧非零推荐元数据纠正。
- 播放回归覆盖：恢复队列首项不可播、单剧准确报错、网络错误保留、不可播队尾补页、过滤空页和推荐耗尽。
- UI 回归覆盖：原生背景出现前后材质选择、相同 tint、黑底渲染不发白。
- 隔离静音原生窗口使用本地 90 秒视频验证成功播放，日志确认时钟、时长和缓冲正常；未使用用户账号或替换安装版。
- MyGo 自动化截图不包含 AVKit/原生材质的最终系统合成；系统窗口截图也未能生成，因此这些截图不作为原生合成层白闪已消失的视觉证据。材质判断依据框架取样实现、状态回归及离屏渲染验证。

诊断命令增加 `playback-diagnose -series <ID>`，仅报告公开元数据和数量，不输出凭据、设备身份或签名播放地址。原生验收命令支持 `-resolve-delay`，便于观察首帧前的状态。

完整 `go test ./...`、IPC/播放/UI 的 `-race` 检查、`go vet ./...` 和 `git diff --check` 均通过。构建产物为 `dist/darwin-arm64/myguo.app`，通过 `codesign --verify --deep --strict`，没有覆盖安装版。
