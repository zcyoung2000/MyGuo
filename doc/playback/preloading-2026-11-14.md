# 推荐流与剧集播放预加载检查

本次针对推荐切换、连续剧集播放和「正在缓冲」检查并修改。保留既有原生播放器、UI、同步和账号隔离修复。

## 已修复的问题

- 旧策略要求当前视频始终保有 5 秒缓存，导致最后不足 5 秒时取消下一条下载。改为：完整缓存的剩余片段可继续预加载；一般情况下用 5 秒开始、2 秒停止的两个阈值，避免反复取消重下。阈值按倍速折算为实际观看时间。当前视频缓冲时仍撤销后台任务以让出带宽。
- 推荐流只准备后两部剧，而播放结束会先续播本剧下一集。现在同时解析下一集元数据，在剩余 30 秒观看时间内将它提为首选，另一名额保留下一部推荐；平时准备后两部推荐。剧集页准备后两集。所有路径仍最多提交两个磁盘预加载项目。
- 切换时立即删除上一条未完成 HLS，导致向回切换无法复用。当前视频有余量时，短暂保留一个最近播放的写入任务，最多 8 秒；更早的历史立即释放。此期间只运行一个后续预加载，为当前视频保留下载容量。当前缓冲、清空窗口或退出时释放保留项。
- 已协商到较低清晰度的预热项目，原先会因与首选清晰度不同而在切入时重新解析并销毁。现在按相同请求意图复用；用户明确选择清晰度时仍能重新协商。
- 预热后切入又精确 seek 同一位置，会使预解码失效。现在保持已准备的播放位置；明确重播或需要恢复其他位置时仍定位。预热能在已生成范围内提前定位到续看进度，超出范围仍保留现有完整文件回退。
- AVKit 预热在 ready 之前调用会无效。现在等待 ready / seek 完成后执行，跟踪进行中与已完成状态，并在切源、定位和倍速变化时使旧预热失效。保留最多三个原生解码器、单个可听播放器。
- 当前视频缺少余量时，先停止后台原生播放器的 EVENT 轮询，再撤销下载任务，避免已暂停的预热播放器重新请求播放列表、把刚取消的下载重新启动。
- AVKit 前向缓冲目标由固定 6 秒改为 `12 × 倍速` 个媒体秒，即约 12 秒观看余量；预热期间允许更新暂停的 EVENT 流。实际可获得缓存仍取决于源端供给。该 API 是目标值，不保证实际缓存长度：[Apple 文档](https://developer.apple.com/documentation/avfoundation/avplayeritem/preferredforwardbufferduration)。
- 增加首帧后缓冲开始、恢复、持续时间和缓存余量日志；首帧耗时不再受旧 ticker 时间戳影响而显示负数。

## 验证

- Go 回归覆盖结尾不足 5 秒、双阈值、倍速余量、后台让带宽、剧集后两集、推荐自动续集、较低清晰度复用、预热切入不重复 seek、解码器预算和上一条保留期限。
- 真实 ffmpeg + 受控 HTTP 上游验证：当前及后续视频在下载未完成时发布可播放片段，切入复用同一写入任务，反向切换复用原任务，过期窗口不重启下载。
- 独立原生 AVKit 程序，使用本地合成视频及逐步扩展的 EVENT HLS，保持生产的 `EXT-X-START` 标签。12 秒测试中，2 倍速预热约 2 秒后切入，105 毫秒开始推进，播放位置持续前进至 17.75 秒，切入后未再次进入缓冲。该结果只证明此受控条件，不代表真实 CDN 或所有网络下都能无缓冲。
- 相同 EVENT 方式的 1 倍速冷启动，约 648 毫秒显示首帧、791 毫秒开始推进，持续播放至 10.74 秒，未进入缓冲。日志为 `/tmp/myguo-preload-cold-trace.log`。
- 最终原生代码再次验证 2 倍速预热切入：138 毫秒开始推进，随后至 17.71 秒持续播放，没有再次缓冲；日志为 `/tmp/myguo-preload-event-2x-final.log`。全量 Go 测试、playback/media race、vet、native check、打包及严格签名验证均通过，产物 25.7 MB。
- 没有通过隐藏「正在缓冲」提示掩盖停顿。保留快速启动方式；没有启用测试中无法证明有益的另一套系统等待策略。

测试日志：`/tmp/myguo-preload-all.log`、`/tmp/myguo-preload-race.log`、`/tmp/myguo-preload-native-check.log`、`/tmp/myguo-preload-vet.log`。原生实测：`/tmp/myguo-preload-event-2x.log`。构建：`/tmp/myguo-preload-build.log`。

构建产物为 `dist/darwin-arm64/myguo.app`，不会自动覆盖 `/Applications`。本次未改动真实账号数据或发送云端互动。
