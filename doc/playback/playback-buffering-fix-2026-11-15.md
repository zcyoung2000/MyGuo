# 进度保存锁冲突与持续缓冲修复

## 用户日志与原因

用户数据目录日志明确记录 `save progress failed: database is locked (5) (SQLITE_BUSY)`，当时磁盘仍有约 44GiB 可用空间。“请检查磁盘空间”的提示错误地把所有存储异常归为磁盘不足。

同一段日志有大量历史上报 `code=100103` 失败与少量限流响应；现有退避按每次本地保存生成的 revision 索引，因此持续更新播放时钟会绕过先前的退避。

播放日志在 70.83 秒、缓存余量约 0.09 秒、2 倍速时反复进入缓冲。旧控制器只对首次加载超时或显式错误切源，首帧之后可以无限等待。现有日志不足以断定源端停止供给的具体原因，因此使用可控故障验证恢复路径。

## 修改

- SQLite 通过连接 DSN 对每条新连接设置 busy timeout 和 synchronous，使用 IMMEDIATE 写事务避免旧读快照升级写入，并把连接池限制为四条。原有单次 PRAGMA 只配置启动时的一条连接。
- 进度事务传入调用者 context；短暂 BUSY/LOCKED 在保存工作线程内有限重试。错误提示只在 SQLite FULL 或 ENOSPC 时说明空间不足，其他失败使用通用保存提示。账号范围和进度、上传意图的原子提交仍受保护。
- 历史上报退避按账号和短剧保持，新的本地进度 revision 不会绕过冷却；最新时钟仍覆盖本地队列，云端失败不会清掉上传意图。没有向真实账号发送测试上报。
- 追踪首帧后的实际播放时钟：缓冲且时钟停止三秒、有可用缓存时尝试恢复一次；停止八秒后使用现有备用完整文件源继续播放。备用源也失败时显示可重试错误，避免无限缓冲。暂停、定位、正常结束和仍在推进的时钟不会触发此恢复。
- HLS 在距离完整剧集预期结尾超过两秒时提前上报 EOF，改为恢复本集，不直接跳过剩余内容。真正片尾和完整文件源仍正常续播。
- 切源以当前时钟或最新 seek 目标恢复，不再跳回更大的旧续看位置；将恢复位置登记为 pending seek，加载期间关闭也不会把初始零时钟覆盖到历史。

## 验证

- 真实 SQLite 锁竞争：占住初始池连接，外部写事务持锁 150ms，进度在新连接上等待后成功提交，历史与上传意图一致。另覆盖包含 URI 特殊字符的路径。
- 模拟上游拒绝：连续十二次新进度更新后仍只发送一次上报，最后一条本地时钟保留。使用测试 HTTP 服务，不触及真实账号。
- 回归覆盖短暂保存失败重试、错误提示分类、缓冲恢复上限、单次恢复尝试、时钟推进重置、暂停/定位/结束保护、提前 EOF 和切源期间保存。
- 真实原生 AVKit、生产控制器和本地 SQLite：本地 fMP4 HLS 故意阻塞第九个片段，2 倍速播放。修复前停在 15.91 秒、缓存余量 0.09 秒，直到 32 秒测试结束都未恢复；修复后停滞八秒切换备用源，保持同一集并继续推进到 46 秒，退出后数据库保存 46.36 秒。日志 `/tmp/myguo-blocked-before.log`、`/tmp/myguo-blocked-after.log`。
- 另用停止更新的 EVENT 前缀验证提前 EOF：修复后同一集切源并推进到 30.35 秒；日志 `/tmp/myguo-prefix-after.log`。最终代码再次验证阻塞片段恢复，同一集持续推进，退出保存 30.17 秒；日志 `/tmp/myguo-blocked-final.log`。
- 全量 Go、playback/store/library/media/IPC race 与 vet 通过；最后的 pending seek 调整又通过 playback/store 回归及竞态检查。日志 `/tmp/myguo-buffer-fix-{all,race,vet}.log`、`/tmp/myguo-buffer-fix-final-target.log`、`/tmp/myguo-buffer-fix-race-last.log`。

这些实测证明故障恢复与本地持久化路径，不代表所有 CDN 或网络都不会缓冲。构建产物为 `dist/darwin-arm64/myguo.app`，没有覆盖安装版或更改真实账号数据。

最终构建与严格签名验证通过。构建日志 `/tmp/myguo-buffer-fix-build.log`。
