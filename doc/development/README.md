# 开发与协作约定

## 开始开发

本项目是原生 macOS 短剧浏览客户端。开始开发前，先检查 `main` 是否包含当前
分支缺少的提交；如果有，先合并 `main`，再继续修改。

## UI 操作与验证

- 同一个 UI 动作连续失败 2 次后，停止并换方法，或直接说明结果。
- 已经能确认目标状态时，不要为了“再确认一次”继续操作 UI。
- 不要反复切换标签页、窗口、菜单或快捷键来测试同一个点。

## 文档组织

专项文档统一放在 `doc/` 的主题目录，入口为 [文档总览](../README.md)。
根目录保留 README、CHANGELOG、LICENSE 和 AGENTS 等约定入口；`CHANGELOG.md`
还由应用更新流程读取，不随专题文档迁移。

- `AGENTS.md` 只提供规则与文档引用，不堆叠实现细节、操作手册和历史复盘。
- 当前架构、维护手册放在对应主题中；有明确时间背景的调查与修复记录保留日期。
- 新增专题文档时同步补充总览，避免继续向 `doc/` 根目录平铺文件。
- 移动文档时修正相对链接、README、代码中的路径和相关测试；上游 MyGo 的
  `docs/` 引用属于外部项目，不要批量改成本仓库的 `doc/`。

## 发布与 CI

发布或修改 CI 前阅读 [发布与自动更新](../release/releases.md)。统一从默认
分支的 `Release` 调度器启动；重发旧版本不重跑旧的失败工作流。
runner 配置或排队错误最多切换一次，代码和签名错误不盲目重试，保留全平台验证。
修改流程后先运行调度器测试，再做 `publish=false` 演练，分别报告排队与执行耗时。
历史经验见 [2026-11-25 发布复盘](../release/release-retrospective-2026-11-25.md)。
