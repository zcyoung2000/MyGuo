# 同一账号身份规范化与历史恢复

用户只打开设置中的“切换账号”，未提交新凭据，却发现历史为空。检查确认：19:24 的账号保存把旧版采用的 `req_id` 改成官方 `biz_user_id`；旧实现把 ID 字符串变化直接当作换号，清空了可见历史。仅凭打开设置的动作不能推断用户真的换了账号。

## 修复

`LoginWithCookies` 继续要求官方响应提供有效 `user_id` 或 `biz_user_id`，不会用 `req_id` 判断登录成功。同账号资料刷新保留数据；旧 `req_id` 只在它仍是当前已保存的账号 ID、请求使用与当前完全相同的 Cookie、并且官方响应包含正式账号 ID 时作为迁移别名。已是正式身份时，仅恢复该正式 ID 明确拥有的待同步历史，不凭响应中的 `req_id` 认领其他遗留队列。

`SetAuthenticatedAccount` 在同一个事务中合并已验证别名的同步队列、恢复缺失的可见历史、保存正式账号身份。队列冲突按 revision 和时间保留较新操作，恢复不覆盖已有进度、不撤销删除和清空记录。没有归属的空 scope 与其他账号的数据不迁移。真正切换到另一个账号仍清空当前可见数据，旧账号待同步操作保留在原账号范围。

设置操作改用 MyGo v0.9.1 的原生 `ButtonBase.OnClick`；打开/收起登录输入区不调用账号服务，不刷新凭据、不改历史。原生按钮提供独立的点击与键盘语义，沿用现有暗色样式。

## 本机恢复

只读请求官方用户信息确认当前正式 ID 与旧队列 ID 属于同一份现存凭据。先创建不含凭据的私有本地备份，并在内存数据库副本演练；实际修复在 `BEGIN IMMEDIATE` 内再次核对当前凭据及账号未变，再迁移已确认归属的队列并补回缺失记录。

本机恢复结果：可见历史从 0 条变为 **81 条**，进度与剧集信息来自原待同步记录；156 条未明确归属的旧上传记录、51 条未明确归属的旧删除记录原样保留。未写入账号凭据，未覆盖安装版。备份位于 `/tmp/myguo-history-recovery-20261115`，目录权限 0700，历史快照权限 0600。无需将真实凭据或账号 ID 写入仓库。
